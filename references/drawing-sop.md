# 绘制与修订 SOP

适用于单色线性和面性。项目参数从对话和实时资产读取，不从本文件固定继承。

## 1. 接收需求与配置

读取本次意图、参考附件、带节点的 Figma 链接、项目规则与项目配置。已有类型新增语义图标，只补本次名称、用途、参考与差异；新项目先走 [首次配置](onboarding.md)，新类型走 [新增类型清单](new-icon-type.md)。

单色状态图标仍可适用，判断依据是实际颜色与几何，不是名字中是否含“状态”。多色参考必须先明确单色重绘方案。

## 2. 定向检查、查重与抽样

只读取目标分类区域、明确目标和必要依赖。查同名、同义及高度近似图标；已有可用资产时提出复用，不加 `_2` 规避重复。抽样至少三个同类型同尺寸正式资产；不足三个记录实际数，零样本用批准的参考建立基准。

记录目标及父级 ID、组件/组件集数量、直接子层、相邻顺序、准确尺寸、结构、描边或填充、颜色绑定、主题、栅格、安全区与辅助线。计数只是本次快照，不存成永久事实。

## 3. 批准包

每个编号列明：语义与名称、线性/面性、准确宽高、目标区域、图层结构、线宽或填充、颜色绑定、视觉依据、允许/禁止范围、回滚办法。

- 新增组件默认可提出 `{语义}_{边长}`、`{语义}_{宽}x{高}`；项目已有命名约定优先，不追溯改名历史资产。
- 往现有组件集中加变体时沿用其属性结构，明确列出容器必要扩展，不把独立组件的短名称规则硬套给变体。
- 图形、基础资产创建、既有组件重构和文件覆盖分别列项。允许同一批准包分别批准，不重复询问已经明确覆盖的动作。
- `a：y`、`a–c：y` 或原生选项是示例；以用户对具体范围的明确意图为准，不把模糊赞同当作整批批准。

## 4. 唯一回滚点

首次正式写入前在 Figma Web 保存一次 `修改前备份_YYYY-MM-DD_需求简称`，核验名称、时间与状态。保存状态不明则停止写入，刷新历史核验，不直接重试。发现同名版本仅记录说明，不自行删除或合并。修订与可选导出复用本次版本。

## 5. 原生绘制

使用基础形状、原生矢量路径与必要布尔操作。普通绘制阶段禁止为导出提前轮廓化、创建“备份”组或生成 SVG。

- 线性：使用已批准的线宽、端点、转角、描边对齐与颜色绑定。
- 面性：使用单色填充和可编辑负形；默认无描边。需要轮廓外观时可按同类正式资产以闭合填充几何表达，不能擅自把它改成另一套描边规范。
- 保持准确画布，非方形不拉成方形。新尺寸不自动缩放旧类型的线宽、栅格与圆角。
- 对已指定目标原位修订，保持组件 ID、名称、尺寸、位置及原稿结构，除非相关变化也已明确获批。
- 保留项目要求的栅格实例，完成后隐藏且锁定。不存在匹配栅格时提出缺项，不复制别的尺寸冒充。
- 工具调用返回所有实际受影响 ID。大读取只返回精简信息，避免因返回数据超限导致变更未提交。

## 6. 结构、视觉与范围复查

结构：名称、尺寸、可编辑性、颜色绑定、直接子层、栅格来源和状态；不含位图、外部 SVG、文字或无关实例；图形未越界。

视觉：100% 真实辨识度，至少400% 检查路径、端点、圆角、交叠、孔洞与边缘，分类总览对比视觉大小与重量。先读安全区和关键辅助线，再判断是否过大；不能把整个画布撑满。几何居中只是起点，可为偏重的蕉身、星芒等非对称形状作有依据的光学微调，不能机械放大所有图标到同一外接框。

交叠图形先确定前后关系，再检查分界和负空间。两根物体不能只合并为一个不辨数量的轮廓，镂空不能依赖背景色遮盖。

仅复扫本次分类、变更节点与依赖；数量变化应由批准项解释。相邻资产意外变化或未知并发变化须先核实，不覆盖用户手动修改。

## 7. 交付与改图

交付编号、Figma Web 节点链接、当前截图、变更 ID、回滚证据和复查记录。技术通过不代表视觉已获用户接受。

回到 [SKILL.md 的格式分支](../SKILL.md#绘制后的必经分支)，询问是否需要 Iconfont。用户退回时只调整对应编号、复查并展示新版本，重新取得格式决定；同任务不重存版本或新建组件。用户明确已结束后提出的新替换属于新任务，单独记录范围与回滚点。
